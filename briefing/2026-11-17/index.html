Malware rode in on a trusted script and hit CNN, Zoom and the BBC. Your small-business site loads outside scripts too. Here's what to check

Attackers broke into Optimizely, a web testing service, and slipped card-skimming code onto the sites of 178 organizations on Monday. You probably don't use Optimizely. You almost certainly load someone else's code on your website. Here's a short list to review this week.

On Monday, visitors to some of the biggest sites on the web got malware from a service those sites trusted. Optimizely, a platform companies use to test and personalize their web pages, says an unauthorized party exploited a vulnerability in its Experimentation product and used it to add malicious JavaScript to some customer projects, per Optimizely's status page.

What happened. Security researcher Scott Helme of Report URI found 188 infected Optimizely scripts belonging to 178 organizations, per BleepingComputer. BleepingComputer confirmed the malicious script loaded, or tried to load, on sites including Zoom, CNN, the BBC, GitLab and Salesforce. The code swapped cryptocurrency wallet addresses for the attacker's, looked for card numbers typed into pages, collected cookies and screenshots, and tried to load iOS exploit kits on iPhones and iPads.

What Optimizely says it did. The company told BleepingComputer it blocked the vulnerable path, deployed a fix, removed the injected code, ended active sessions, revoked tokens and reset access for affected user accounts. Report URI found one customer's script was cleaned and then re-infected, which suggests the attacker still had access at that point, per The Hacker News.

Why a small business should care. Your website almost certainly loads code from other companies: analytics, ad pixels, chat widgets, booking tools, review badges. Each of those runs with the same power as your own code. If one of those companies gets broken into, your visitors get whatever the attacker adds, and your site's name is on it. Optimizely's customers didn't do anything wrong on Monday. The weak point was a vendor.

One detail worth knowing. Report URI recommends a Content Security Policy, a browser rule that limits which outside code a page may run and where it may send data. It also notes that simply allowing cdn.optimizely.com would not have helped, because the bad code came from that same host, per The Hacker News. A policy helps most when it also limits where scripts can send data.

Action items for this week.
1. If you visited a big-name site Monday and paid by card, watch your statements. If you sent crypto that day, compare the address you paid against the one you meant to pay, per BleepingComputer.
2. Update iPhones and iPads. Report URI advises iOS 18.7.3 or later, or iOS 26.3 or later, for anyone who visited an affected site, per The Hacker News. It's a good idea regardless.
3. List the outside scripts on your own site. Ask whoever built it, or check your site's settings and plugins. Remove anything nobody uses anymore. Old tracking pixels and abandoned widgets are pure risk.
4. Keep extra scripts off your payment page. Take card details through your payment provider's own hosted fields or checkout page, so outside scripts on your site never touch card numbers, per The Hacker News.
5. Lock down the vendor accounts. Every service that can change code on your site (web host, site builder, tag manager, plugins) needs multi-factor sign-in and only the people who still need access.
6. If you use Optimizely, follow Report URI's checklist: review your project JavaScript and experiment code for anything you didn't write, rotate API tokens and check who can write to the account, per The Hacker News.
