Attackers have been breaking into VMware vCenter since September. If your servers run on VMware, patch vCenter this weekend

Broadcom has fixed a critical vCenter flaw that lets someone with network access skip the login, and Google's Mandiant says a state-backed group was already using it. Here's how to tell if you're affected and what to do first.

Broadcom released an emergency fix on Nov. 19 for CVE-2026-123890, a critical authentication bypass in VMware vCenter Server rated 9.8 out of 10, per its advisory VMSA-2026-0009. Broadcom says an attacker with network access to vCenter can bypass authentication and gain unauthorized access, and that there is no workaround. CISA added the flaw to its Known Exploited Vulnerabilities catalog on Nov. 20.

Who's using it. Google's Mandiant and Threat Intelligence Group say a suspected Chinese state-sponsored group it tracks as Armory Castle exploited the flaw starting in early September, per BleepingComputer. In the attack Mandiant described, the group first broke into a BeyondTrust Remote Support appliance, moved through internal Linux systems, and then used the vCenter flaw to create an administrator account and steal the vCenter directory database.

Why it matters if you're a small business. vCenter is the console that runs your VMware servers. Whoever controls it controls every virtual machine under it. Mandiant says the attackers went on to reach ESXi hosts and pull files from virtual machines, including Windows Active Directory database files, per BleepingComputer. Censys notes the attack path also allows forged sign-in tokens that can get past MFA. If your file server, accounting system or domain controller lives on VMware, this is the patch to do first.

The fixed versions. From Broadcom's advisory:
- vCenter 8.0: update to 8.0 U3m
- vCenter 9.0.x: update to 9.0.2.0200
- vCenter 9.1.x: update to 9.1.1.0200
- VMware Cloud Foundation 5.x: update to 5.2.5
- vCenter 7.0: no public fix. Broadcom says to contact its support if you have an extended support contract.

Action items for this weekend.
1. Find out if you run vCenter at all. If you have one or two standalone ESXi hosts with no vCenter, this flaw doesn't apply, but ask whoever manages your servers to confirm.
2. Check the version. Compare it to the list above. Anything older needs the update.
3. Take a snapshot or backup of vCenter, then patch. Broadcom calls this an emergency update.
4. Keep vCenter off the internet. The management console should only be reachable from your internal admin network or VPN. Broadcom says network restrictions and firewall rules can reduce exposure while you schedule the update.
5. Still on vCenter 7.0? Without an extended support contract there's no fix. Lock down network access to it now and start planning the upgrade.
6. Patch the doors in, too. This attack started at a remote-support appliance. Make sure remote-access tools, VPNs and firewalls are on current versions.
7. If your vCenter was reachable from outside before you patched, have someone review it for new admin accounts and unfamiliar logins. Censys says a vCenter attackers could reach while it was unpatched needs review.
